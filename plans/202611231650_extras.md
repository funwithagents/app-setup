# Extras: installed, carried, installed by uv

**Status:** Done

Implements `specs/extras.md`: what module-setup does with a requirement a contract returns. It leaves out the Setup tab that shows the statuses and the install button (the UI spec).

## Scope

- `src/module_setup/extras.py` — `RequirementStatus`, `requirement_status`, `host_extras`, `Installer`, `find_installer`
- `tests/test_extras.py` — functional tests over fake distributions written as `.dist-info` folders, and a stand-in `uv` executable
- `AGENTS.md`, `specs/_index.md`, `specs/_overview.md` — the project map row, the index row, the planned-specs table

## Steps

1. `requirement_status`: the distribution, then what each named extra adds (the `Requires-Dist` entries whose marker names it), each entry kept only when its marker holds on this machine, checked for presence and version, its own extras entered recursively with a guard against cycles.
2. `host_extras`: the requirement's own extras when the host is its distribution; otherwise, for each extra, the first host extra whose entries name that distribution with that extra.
3. `find_installer`: the project directory from the host's `direct_url.json`, its `uv.lock`, `uv` on the `PATH`; a sentence for each refusal.
4. `Installer`: the `uv sync --inexact --frozen --no-default-groups` command (`--active` outside the project's `.venv`), run with its output streamed, one at a time, import caches invalidated afterwards.
5. Tests.

## Verification

`uv run ruff check .`, `uv run ruff format .`, `uv run pyright`, `uv run pytest` all pass (61 tests), also on Python 3.11. Tried by hand against two real project environments: statuses and carriers came out right. The install itself is tested against a stand-in executable; a run against the real uv belongs to the live tier and is not written yet.
